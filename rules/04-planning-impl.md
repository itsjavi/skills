## 04 - Planning and implementation

- Do not over-plan routine local changes.
- For non-trivial work, identify important assumptions, constraints, acceptance criteria, and affected areas before
  implementation.
- When a task contains a material unresolved product, UX, architecture, data, security, or destructive-operation
  decision, surface it instead of silently guessing.
- Do not interrupt the user for low-impact implementation details that can be inferred safely from repository
  conventions.
- When an accepted plan or task specification exists, treat it as the implementation contract unless concrete evidence
  reveals a contradiction or blocker.
- If implementation uncovers a new consequential decision, return to planning rather than forcing the existing approach
  through.
- Verify the result against the task's acceptance criteria, not only against passing tests.
