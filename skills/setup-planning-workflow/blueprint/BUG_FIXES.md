# Bug Fixes

Index of scoped bug reports and their proposed or completed fixes.

Use this file for defect work that should be tracked separately from roadmap milestones and implementation plans. Each
linked record in `bug-fixes/` keeps the report, reproduction notes, impact, root-cause notes, proposed fix, validation
plan, and final outcome in one place.

For workflow conventions, file naming, statuses, and templates, see [Guide](GUIDE.md). For active parallel work, see
[Coordination](COORDINATION.md). For durable roadmap work, see [Milestones](MILESTONES.md). For automated checks and
manual QA coverage, see [Automated Checks](CHECKS.md) and [Manual QA](MANUAL_QA.md).

## Index Rules

- Add each new bug-fix record to this file when it is created.
- Keep index rows brief; store reproduction steps, diagnosis, proposed fix, validation, and outcome in the linked
  `bug-fixes/` record.
- Update status and fixed date when the fix lands or the record is closed.
- Link related plans, checkpoints, decisions, business rules, checks, manual QA flows, setup docs, or research notes
  only when they are directly relevant.
- Promote the work into a milestone plan when the fix expands into broad feature work, durable architecture changes,
  migrations, cross-domain behavior, or multi-phase delivery.
