`plugins/<plugin>/skills/<skill>/`. If you prefer a standalone skill, copy its whole directory into `~/.agents/skills`,

manual updates. Remove any older standalone copies when switching to their plugin to avoid duplicate skills.

#### Plugins setup

Add this repository as a marketplace, then install the plugins you want. Each app uses its own catalog and plugin
manifest. Each plugin shares one `skills/` directory across both apps.

The root `.agents/` and `.claude-plugin/` directories contain marketplace catalogs used directly when an app adds this
repository. Keep them at these discovery paths so Git installation works. They are not project settings to copy into
your project. Each plugin’s `.codex-plugin/` and `.claude-plugin/` directories stay inside its package and travel with
it when the package is installed or copied.

| App                            | Marketplace catalog                                                    | Example plugin manifest                                                                      |
| ------------------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Codex                          | [`.agents/plugins/marketplace.json`](.agents/plugins/marketplace.json) | [`plugins/webcraft/.codex-plugin/plugin.json`](plugins/webcraft/.codex-plugin/plugin.json)   |
| Claude Desktop and Claude Code | [`.claude-plugin/marketplace.json`](.claude-plugin/marketplace.json)   | [`plugins/webcraft/.claude-plugin/plugin.json`](plugins/webcraft/.claude-plugin/plugin.json) |

##### Codex Desktop

1. Open **Plugins → Add → Add Marketplace** and add `https://github.com/itsjavi/skills.git`, or select the root of a
   local checkout of this repository.
2. Browse **Local Plugins** (`local-plugins`), open **Webcraft**, and install it. Adding a marketplace makes its catalog
   available; you still need to install each plugin.
3. Start a new task to load the installed skills. Refresh the app if the catalog has not appeared yet.

With the Codex CLI, add the repository and install Webcraft:

```sh
codex plugin marketplace add itsjavi/skills
codex plugin add webcraft@local-plugins
```

For a local checkout, replace the first command with `codex plugin marketplace add /path/to/skills`. Keep the checkout
intact: `.agents/plugins/marketplace.json` resolves each `./plugins/<plugin>` from the repository root. The personal
marketplace at `~/.agents/plugins/marketplace.json` is a separate setup and is discovered automatically.

See the official [Codex plugin guide](https://learn.chatgpt.com/docs/build-plugins).

##### Claude Desktop

1. Open **Customize → Plugins**. For Cowork, open the **Cowork** tab first.
2. Under **Personal plugins**, click **+ → Add marketplace**.
3. Choose **Add from a repository** and enter `https://github.com/itsjavi/skills.git`.
4. Browse the **itsjavi-skills** marketplace and install **Webcraft**.
5. Type `/` or use the **+** menu to select a bundled skill, such as `webcraft:react-development`.

The same marketplace dialog supports **Browse Anthropic sources** for additional curated catalogs. Repeat the flow to
add other GitHub repositories or Git URLs alongside this marketplace.

For local changes before publishing, upload a ZIP containing the contents of the selected plugin directory, such as
`plugins/webcraft/`, including the hidden `.claude-plugin/` directory. Keep `skills/` and any bundled assets, scripts
and references at the ZIP root.

Claude Desktop's Chat and Cowork plugin setup is managed through **Customize**. Use a session with access to the
repository and tools required by the selected skill. Installing a plugin does not install external dependencies such as
the Coolify CLI, Blender or Godot.

Source: [Use plugins in Claude](https://support.claude.com/en/articles/13837440-use-plugins-in-claude).

##### Claude Code, including the Desktop Code tab

In a terminal, register this marketplace and install Webcraft:

```sh
claude plugin marketplace add itsjavi/skills
claude plugin install webcraft@itsjavi-skills
```

For a local checkout, replace the first command with `claude plugin marketplace add /path/to/skills`. Inside the
interactive CLI, the equivalents are `/plugin marketplace add itsjavi/skills` and
`/plugin install webcraft@itsjavi-skills`. Invoke a skill with `/webcraft:react-development`.

In a local Desktop Code session, use **+ → Plugins → Add plugin** to browse configured marketplaces, or **Manage
plugins** to manage installed plugins. Cowork uses its own **Customize** configuration rather than the CLI's `~/.claude`
directory. See [Claude Code Desktop](https://code.claude.com/docs/en/desktop#install-plugins).

Claude Code accepts GitHub `owner/repo` names, full Git URLs, local directories and direct marketplace JSON URLs. This
repository uses relative plugin paths, so add the Git repository or local checkout; a raw JSON URL downloads only the
catalog and cannot resolve those paths.

Use `claude plugin marketplace list` to list configured marketplaces and
`claude plugin marketplace update itsjavi-skills` to refresh this catalog. See the official
[installation guide](https://code.claude.com/docs/en/discover-plugins) and
[marketplace format](https://code.claude.com/docs/en/plugin-marketplaces).

#### Getting updates

Git is the shared source for all plugins. After a release reaches the marketplace’s Git branch, clients can fetch it.
Claude compares the installed plugin version with the version in its manifest, so a new commit must also include a
version bump for changed plugin content to replace a cached installation.

In Claude Code, third-party marketplace auto-updates are disabled by default. Open `/plugin`, choose **Marketplaces**,
select **itsjavi-skills**, and enable **auto-update**. Claude then checks at startup and prompts you to reload updated
plugins. To update manually:

```sh
claude plugin marketplace update itsjavi-skills
claude plugin update webcraft@itsjavi-skills
```

Repeat the plugin update command for other installed plugins. In Claude Desktop, manage updates in **Customize →
Plugins**. In Codex, use the marketplace and installed-plugin controls to refresh and update; start a new task after
updating. A Git push publishes the files but does not force every running client to reload immediately.

See [Claude’s update settings](https://code.claude.com/docs/en/discover-plugins#configure-auto-updates) and
[version-based plugin updates](https://code.claude.com/docs/en/plugin-marketplaces#version-management).

## Maintaining plugins and releases

All plugins use one shared release version from the root `package.json`. A release bumps every plugin, including
unchanged ones, so this small collection has one consistent release history. Keep skill instructions and their
supporting files inside their owning plugin.

Edit plugin metadata in `plugins/<plugin>/.codex-plugin/plugin.json`. The generator copies its shared fields into the
Claude manifest, synchronizes every manifest’s version, and rebuilds both marketplace listings. The marketplace entries
use local paths and omit duplicate plugin versions. Marketplace names, display metadata and existing Codex installation
policies are preserved. The README catalogs are generated from the packaged skills and plugin metadata.

After editing skills or metadata, run:

```sh
pnpm install --frozen-lockfile
npm run build
npm run check
npm test
```

Commit the changes, then create a release from a clean working tree:

```sh
npm version patch -m "chore(release): %s"
```

Use `minor` or `major` when appropriate. npm updates `package.json`, then the `version` hook synchronizes and validates
the plugin manifests and catalogs and stages the generated changes. npm includes them in its release commit and Git tag.
The hook belongs in `version` because `postversion` runs after the commit and tag already exist. Nothing is pushed
automatically. Push the release commit and its tag when ready to publish it to the marketplace repository.

To synchronize manifests with the current root version without changing it, run:

```sh
npm run version:sync
```

This also refreshes marketplace metadata and never stages, commits or tags files. For a version bump without staging,
committing or tagging, use `npm version patch --no-git-tag-version`. For a full metadata and README catalog refresh
without bumping the version, use `npm run build`. `npm run check` and CI reject stale generated files, missing icons and
broken local skill links. The release tests run real npm version commands in temporary repositories.

See the official [npm version lifecycle](https://docs.npmjs.com/cli/v11/commands/npm-version/#description).

## Vendored upstream skills

Some packaged skills are mirrors of skills maintained in another repository. `scripts/upstream-skills.json` lists each
one with its upstream repository, branch, source directory, license and the commit the local copy came from. Today that
is [react-router](plugins/webcraft/skills/react-router/SKILL.md), mirrored from the MIT licensed
[`.agents/skills/react-router`](https://github.com/remix-run/react-router/tree/main/.agents/skills/react-router) in
`remix-run/react-router`.

To pull the latest upstream revision, run:

```sh
npm run upstream:sync
```

Each listed directory is replaced with the upstream files for the tip of its configured branch, the resolved commit is
recorded in the registry, and the README catalog is regenerated because a mirrored skill can change its own name or
description. The command reports the commit it landed on, then runs `pnpm format`, so a mirror follows this repository’s
formatting instead of the upstream file layout: prose is rewrapped and code samples are restyled. The sync needs network
access to clone from the upstream repository, so it stays out of `npm run check` and CI.

Do not hand-edit a mirrored file, because the next sync overwrites it. Improvements belong upstream. Fork the skill
under a different name when this repository needs to diverge.

To mirror another skill, add an entry to the registry and run `npm run upstream:sync`. `npm test` rejects a registry
entry that is not a packaged skill or has no recorded commit.
